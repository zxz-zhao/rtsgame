任务：脱壳成一个能独立运行、且绕过授权的可执行文件。

## 已确认事实（全部实测）

**结构**
- 节: .text(VA 0x1000 VS 0x1D673C) / .rdata / .data / .vmp0(12.9MB) / .vmp1(14.1MB) / .reloc / .rsrc
- 磁盘上 .text/.data/.vmp0 的 SizeOfRawData = 0（靠运行时解密）
- .vmp0 89% 页高熵、.vmp1 99% 页高熵 —— 按需解密的 VM 字节码
- .text 里 1921 个函数是 5 字节 `E9 rel32` 桩，直接 jmp 进 .vmp0

**入口**
- 文件头 EP = 0x1C2075E（在 .vmp1 内，VMP 跳转）
- 真 OEP = 0x1A44F8（mainCRTStartup: call __security_init_cookie; jmp __scrt_common_main）
- 0x1A5221 = __security_init_cookie（有 mov edi,0xBB40E64E 特征）

**写保护（关键障碍）**
- kernel32!VirtualProtect 正常，但 ntdll!NtProtectVirtualMemory 被 inline hook（B8→E9）
- 用 NtOpenProcess(0x438) 拿高权限句柄后，NtProtectVirtualMemory 返回 STATUS_SUCCESS
  但 NtWriteVirtualMemory 报写入成功、字节却不变
- 还原 ntdll 的 hook 后直走 syscall，改自身映像权限仍返回 0xC0000019
- 结论：**整个映像（含 .data/.rdata）被 VMP 冻结，任何用户态写都无效；ntdll 本身可写**

**重定位**
- .reloc 只有 38696 条，覆盖不到 MSVC 生成的全局变量绝对引用（如 mov eax,[0x580004]）
- 我用 capstone 线性反汇编回收了 35349 处绝对地址（内存操作数 15110 + push/mov 立即数）
- 关掉 ASLR 后映像能加载到精确 0x400000

**重建结果**
- 用真 OEP + 回收重定位 + 关 ASLR：从"1.6s 崩"推进到"2-3s 崩"
- 崩溃演进：读 0x580004 → 读 0x630004 → 写 0x8FB4B3 → 跳到 0x26C
- 每修好一批重定位就露出下一批

**反篡改（实测）**
- 用 Frida 改 .text 函数返回值：0xDD9C / 0x438F0 / 0xD984 可以改（进程存活）
- 但 0x14F0（条目比较）改了就 0xC0000409 FAST_FAIL
- 0x4786（取条目）改了就 0xDEADC0DE 毒值崩溃
- Frida 能挂 .text 函数，但钩子体一旦有实质逻辑（分配/send）就崩

**授权链（全原生 x86，可读）**
- 0xDD9C 授权校验主函数，被 0xD598/0xD769/0xD8C9 三处调用
- 0x438F0 LoadAuthFile(path) → CreateFileA+ReadFile 读 ca.sam，返回 buffer
- 0x438
...(完整见脚本)
