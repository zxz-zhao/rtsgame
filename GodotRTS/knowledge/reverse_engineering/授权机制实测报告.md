# 大玩家.exe 授权机制实测报告（方案 A：运行时补丁）

- 样本：`H:\soft\大玩家\完整包\大玩家.exe`（VMProtect 3.x 保护，按需解密）
- 方法：正常启动 + frida attach（**不能用 spawn**，VMP 会检出并拒绝创建窗口）
- 工作副本：`_re_work\bin\`（未动原目录）

## 一、结论（实测，非推测）

> **这个样本的授权没有拦截任何主工作流。点「登陆」直接进启动器主界面，
> 与 ca.sam 状态、帐号密码内容全部无关。**

### 实测矩阵

| 用例 | `ca.sam` | 凭据输入 | 点击「登陆」结果 |
|---|---|---|---|
| A | 清空 | 预填 `2235` + 8 位密码 | ✅ 进主界面 |
| B | 清空 | **空** | ✅ 进主界面 |
| C | 清空 | **假 `99999999` / `badpass123`** | ✅ 进主界面 |
| D | 全部状态清空 + 空凭据 | **全新环境** | ✅ 进主界面 |

四组用例**零差异**，且**全程没有弹出任何 MessageBox**（连"帐号或密码错误"都没有）。

## 三、VMProtect 环境下的工具链适配（踩坑记录）

这套环境有几个非显然的坑，记录下来避免重走：

### 3.1 必须用 attach，不能用 spawn

`frida.spawn()` 会把目标以 DEBUG 标志挂起启动，**VMP 检出后直接拒绝创建任何窗口**
（实测：spawn 模式下进程 0 个窗口；正常启动则有 3 个）。

```python
# 正确做法
proc = subprocess.Popen([exe], cwd=workdir)   # 正常启动
time.sleep(5)                                  # 等窗口出来
sess = frida.get_local_device().attach(proc.pid)   # 再 attach
```

### 3.2 Frida 17 移除了旧 API

```javascript
// 17.x 已删除，调用会抛 TypeError: not a function
Module.getExportByName('kernel32.dll', 'GetProcAddress')

// 正确写法
var m = Process.getModuleByName('kernel32.dll');
var es = m.enumerateExports();
for (var i = 0; i < es.length; i++)
    if (es[i].name === 'GetProcAddress') addr = es[i].address;
```

### 3.3 按钮在嵌套子窗口里

`EnumWindows` 只能拿顶层窗口。登录按钮在 `#32770 → #32770 → Button` 两层嵌套里，
必须递归 `EnumChildWindows`。注意 `EnumChildWindows` 本身已递归，再手动递归会重复。

点击用 `SendMessageW(hwnd, BM_CLICK=0x00F5, 0, 0)`。

### 3.4 窗口尺寸与实际内容不符

登录窗口 `GetWindowRect` 报 `323x326`，但内部控件延伸到 x=1167。
`PrintWindow` 会被裁切。**改用整屏 `BitBlt` + 按控件最大范围裁切**才能拿全。

## 五、需要真补丁时的落点

如果后续遇到真正拦人的版本（例如换了新的 `ca.sam` 校验或加了服务端校验），
按优先级用这些落点：

1. **`大玩家.exe+0x443EE`** — `ca.sam` 轮询点，授权状态读取的核心循环
2. **`大玩家.exe+0x28E34`** — 机器码采集点（IOCTL `0x2D1400`）
3. **`大玩家.exe+0x4390B`** — 物理盘序列号读取
4. **`MessageBoxW/A`** — `bypass.py --patch` 已实现自动屏蔽授权类错误提示
5. **`jd.dll` 的 19 个导出** — 若换用动态解析，在 `GetProcAddress` 返回点改函数指针
