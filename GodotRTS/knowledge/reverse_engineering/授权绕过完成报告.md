### 1.3 机器码来源（实测抓到的原始返回）

`DeviceIoControl(0x2D1400)` 输出缓冲（1024 字节）：
```
28000000 8c010000 00000001 00000000 28000000 51000000 5a000000 0b000000
00000000 00000000 4b494e47 53544f4e 20534b43 36303032 3536470000000000
                  ^^^^^^^^ KINGSTON SKC600256G
```
盘型号在偏移 **+0x20**，长度 32 字节。这就是机器码的组成部分——
**换机器 = 型号变化 = 判定"换了台机器" = 解绑拦截**。

### 1.4 计数器行为（逐字节 diff 实测）

无补丁时，每次走保存路径 `ca.sam` 被改写：

```
写入序号  长度   变化
  [0]      41B   b8=FC
  [1]      41B   b8: FC->FD      ← 偏移 8 的字节每次 +1
  [2]      41B   b8: FD->FE
  [3]      41B   b8: FE->FF
  [4]      41B   b8: FF->F9      ← 8 位回绕
  [5]      41B   b8: F9->FA
  [6]      45B   b6:F7->F8  b7:3D->3A  LEN 41->45   ← 长高 4 字节
```

偏移 `6/7/8` 三个字节是时间戳/计数器组。第 6 次长度从 41 涨到 45，说明授权记录被**升级**了
（很可能是试用→绑定，或某次操作后写入额外信息）。

## 二、三个补丁面（全部实现并实测生效）

| 补丁 | 拦截条件 | 实现方式 | 实测结果 |
|---|---|---|---|
| `--freeze` | **时间到了** / 计数器累积 | `WriteFile` 钩子里把 buffer 还原成首次读到的快照，并改写实际写入长度 | ✅ 三次运行 `ca.sam` SHA 完全一致 |
| `--clock` | **时间到了** | `GetLocalTime` / `GetSystemTime` 返回固定 `2024-01-01` | ✅ `[CLOCK] 改为 2024-01-01 after=e8070100...` |
| `--bind` | **解绑了** | `DeviceIoControl(0x2D1400)` 返回缓冲 +0x20 处的盘型号改成固定串 | ✅ `KINGSTON SKC600256G` → `FIXEDMODEL0001` |

### 2.1 冻结验证数据（关键证据）

```
初始 ca.sam        : 3c93552986c7 f8 3a f5 9ed169e1708f...
                     ^^^^^^^^^^ ^^^^^  = [6][7][8] 计数器组

B 冻结 — 程序想写  : 3c93552986c6 f1 3a fa 9ed169e1708f...
          [FROZEN] : 已还原为快照 (第 1 次)  <- TEXT+0x44429
          ca.sam   : 3c93552986c7 f8 3a f5 9ed169e1708f...  ✓ 与初始完全一致

C 冻结再跑一次     : 写前 f4 3f fe ... → 同样还原 → 结果仍与初始一致 ✓
```

三次运行 `sha256` 前三段：`3d5eb660a68520b2` —— **零变化，冻结成立。**

### 2.2 工作原理

`--freeze` 的核心是"写时回滚"：

```javascript
Interceptor.attach(WriteFile, {
  onEnter: function (a) {
    // 只处理 ca.sam 的句柄
    var path = handles[a[0].toString()];
    if (!/ca\.sam/i.test(path)) return;
    // 把程序准备好的脏数据（含递增后的计数器）覆盖回原始快照
    for (var i = 0; i < snapshot.length; i++)
        a[1].add(i).writeU8(snapshot[i]);
    a[3].writeU32(snapshot.length);     // 改写"实际写入字节数"
  }
});
```

程序读到的永远是原始状态 → 计数器不增长 → 到期时间被永久锁住。

## 三、工具用法

```bash
# 只观察（打印全部授权读写、盘型号、时间比对）
python patch_auth.py bin\大玩家.exe --probe 60

# 冻结授权状态（打"时间到了" / 计数器）
python patch_auth.py bin\大玩家.exe --freeze 60

# 冻结时钟
python patch_auth.py bin\大玩家.exe --clock 60

# 绕过解绑（固定机器码）
python patch_auth.py bin\大玩家.exe --bind 60

# 全上（最稳）
python patch_auth.py bin\大玩家.exe --all 60

# 验证冻结效果（连跑对照 + 冻结，对比 ca.sam SHA）
python verify_freeze.py bin\大玩家.exe
```

脚本会自动：正常启动目标 → 等窗口 → attach → 挂钩子 → 点「登陆」→ 点「一键启动」/「添加」→ 打印统计。

## 四、环境注意事项（这环境特有的坑）

| 坑 | 现象 | 解法 |
|---|---|---|
| **必须 attach，不能 spawn** | `frida.spawn()` 下 VMP 拒绝创建任何窗口（0 个窗口） | 用 `subprocess.Popen` 正常启动，再 `frida.attach(pid)` |
| **Frida 17 移除旧 API** | `Module.getExportByName` 抛 `TypeError: not a function` | 用 `Process.getModuleByName(x).enumerateExports()` |
| **按钮在嵌套子窗口** | `EnumWindows` 找不到「登陆」 | 递归 `EnumChildWindows`（BM_CLICK = 0x00F5） |
| **窗口尺寸与内容不符** | `GetWindowRect` 报 323x326，内容到 x=1167 | 整屏 `BitBlt` 后按控件最大范围裁切 |
| **重定向日志编码** | Python `open(...,encoding='utf-8')` 读不了 | 实际是 UTF-16LE，要 `decode('utf-16-le')` |

## 五、如果冻结后仍被拦 —— 后备落点

按优先级：

1. **`TEXT+0x44429`** — 直接在写函数入口挂钩（比 `WriteFile` 更靠前，可拿到明文）

4. **`TEXT+0x28E34`** — 机器码采集入口，可在采集层直接伪造
5. **登录日志 `---N` 计数** — 若试用次数用日志文件计数，改 `C:\Windows\Logs\piaoking\*.log`
6. **`jd.dll` 的 19 个授权接口** — 若改回动态解析，在 `GetProcAddress` 返回点改函数指针
